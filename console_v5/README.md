# GridTriage Console v5

`app_v2.py`의 한 화면 콘솔을 v5 엔진에 연결하고, 분석가 검토(승인·기각·철회)를 더한 별도 콘솔이다.
`app.py`, `app_v2.py`, `pipeline/live.py`는 바뀌지 않는다.

```bash
python -m pipeline.v5.enroll seed            # 최초 1회: 사례 기억 시드 (dataset/real 필요)
.venv/bin/streamlit run console_v5/app.py
```

## 화면

| 영역 | 내용 |
|---|---|
| 사이드바 | 판정 엔진 **v5 (기본) / v4 (비교)**, **분석가 이름**(승인·기각·철회에 필수), v5 설정(사례 저장소, 연구 대기열, 게이트 (b), 자동 연구, 외부 문헌 검색) |
| 타일 | app_v2 타일 + **분석가 검토**: 대기 건수, 미확인(고정) 건수, 연구 중 건수 |
| 최신 판정 | app_v2 내용 + **LLM 원 판정 → 게이트 결과**(카드-사례 불일치 / 정상 사례 불일치 / 등록 사례 일치), 클래스별 사례 일치도, 연구 상태 |
| 상세 › 판정 이력 | v5 판정의 게이트·사례·채널 원자료 |

## 분석가 검토

- **대기 사례**: v5 엔진의 모든 경보. 한 번이라도 unknown이었던 경보는 🟠 미확인으로 고정되어 위에 온다.
  재분석 이력, 사례 일치도, 연구 결과(가설·근거 문헌)를 보고 결정한다.
  - 승인: 라벨 선택(기존 카드, normal, 또는 새 클래스 snake_case) + 사유 → 사례로 등록. 실행 중 엔진은 다음 판정부터 사용
  - 기각: 사유 → 등록하지 않음. 기각도 원장에 남는다
- **승인 원장**: 결정 이력(시드 숨김 가능), 무결성 검사(해시 체인·사례 파일), 사례 철회
- **사례 기억**: 라벨별 사례 수(시드/등록), 분석가 등록 클래스 목록

새 공격을 등록하면 닮은 새 정상 작업(예: LLM 서빙)이 그 공격으로 끌려갈 수 있다. 같은 날 그 정상 작업도
`normal`로 등록한다 (RESULTS_v5.md §7.2).
